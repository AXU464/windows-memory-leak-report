# Windows 11 非分页池内存泄漏：排查与修复报告

> **机型**：ASUS 笔记本 · Windows 11 25H2（build 26200.9168，家庭中文版）· 16GB RAM · RTX 4050 + Intel UHD


---

## 摘要
- **症状**：开机后内核非分页池以 200～616 MB/min 持续泄漏，约 15 分钟耗尽 16GB 内存，系统卡死，重启后循环往复。
- **根因**：系统过滤驱动 **FileCrypt（`filecrypt.sys`）** 扣留 D: 卷上的 I/O 请求不完成，导致内核对象随被扣请求持续堆积。
- **修复**：`sc config FileCrypt start= disabled`，重启后泄漏归零（实测 -0.3 MB/min，历史同期 +329～616 MB/min）。
- **收尾**：泄漏解除后成功执行就地升级重装系统（此前会因内存耗尽而失败），组件库损伤一并修复，问题全部解决。

---

## 一、问题背景：交付ai进行磁盘清理引发的连锁故障

2026-09-04 的一次磁盘清理操作造成两处破坏：

1. **WinSxS 组件库**：4443 个旧版本组件的 manifest 被直接删除 → Windows Update、系统回滚、DISM 修复能力受损。
2. **AppX 状态库**（StateRepository-Machine.srd）损坏 → 登录后黑屏约 5 分钟（Shell 组件启动时阻塞等待损坏的库）。

附带破坏：火绒损坏、部分系统目录被删、大量服务启动类型被改动。

随后暴露出更严重的问题：**内核非分页池以 200～616 MB/min 持续泄漏**，约 15 分钟耗尽内存、系统卡死，重启循环往复。

## 三、内存泄漏：现象与定位

- 实测：开机 2 分钟非分页池 ~1,795 MB（正常应 300～800 MB）、6 分钟 ~3,427 MB，峰值 8,078 MB 时可用内存跌至 85～128 MB、系统卡死。
- 佐证：全部进程的 Pool Nonpaged Bytes 合计仅 ~6.5 MB → 泄漏不归属任何进程，是纯内核驱动分配。
- 跨账号复现：为排查而新建的账号同样存在泄漏，只是速率低于主账号（新账号环境更干净、后台负载更小）——进一步证明泄漏是系统级驱动问题，与账号内软件无关。

### 池标签定位

用 `NtQuerySystemInformation(22)` 直接读取内核池标签（与 poolmon 同源数据）。泄漏表现为**文件 I/O 结构「四件套」同步上涨**：

| 时间（开机约） | 非分页池 | Scbf | FMic | Irp | File | ismc |
|---|---|---|---|---|---|---|
| 4 分钟 | 2,602 MB | 637 MB | 367 MB | 326 MB | 125 MB | 337 MB |
| 8 分钟 | 3,841 MB | 1,117 MB | 674 MB | 593 MB | 192 MB | 337 MB（未涨） |

- `Scbf`（内核存储划痕缓冲）是泄漏主体积；`FMic/Irp/File`（过滤管理器 IRP_CTRL、IRP、文件对象）近 1:1 同步增长 → 经典 minifilter 泄漏特征：**IRP 发出后未完成、文件对象未关闭**。
- `ismc`（Intel RST）虽占 337 MB，但多轮快照零增长 → 静态基线，排除。

### 排除项

VMware（卸载前后照漏）、NVIDIA 独显（禁用反而加速）、Intel 核显（相关 Tag 仅数 MB）、Intel RST（静态基线）、第三方 VPN/TUN 驱动（按用户要求不涉入）——均排除。

## 四、排查时间线：从怀疑 WdFilter 到实锤 FileCrypt

> 排查工作主要在新账号下进行，关键实验由该账号侧的 AI 助手（ZCode）提权执行。

### 4.1 怀疑 Defender 过滤驱动（WdFilter）

| 状态 | WdFilter 是否加载 | 泄漏速率 |
|---|---|---|
| 安全模式 | 不加载 | ~0 |
| 正常 + 引擎全停 | 加载 | 270 MB/min |
| 正常 + 关实时防护 | 加载 | 346 MB/min |
| 正常全开 | 加载 | 350～616 MB/min |

关扫描开关只降约 44%，说明泄漏主体在驱动拦截路径。但运行时无法卸载 WdFilter 验证：`fltmc unload` 报 0x801f0010（DO_NOT_DETACH，运行期不可卸载），注册表写入又被内核安全层（KslD.sys）拦截。改用 WinRE 离线改注册表禁用：

| 轮次 | 禁用对象 | 结果 |
|---|---|---|
| 1～2 | WdFilter（+ WdBoot / WdNisDrv / WinDefend） | 全部 Stopped，泄漏 **440 MB/min 依旧** |
| 3 | 再加 UCPD + CldFlt | **401 MB/min 依旧** |

→ WdFilter、UCPD、CldFlt 均非主漏桶。

### 4.2 决定性实验：卸载 FileCrypt

重启后提权，逐个卸载仍在运行的过滤驱动：

| 阶段 | 非分页池 | 速率 |
|---|---|---|
| 基线 | 1,501 → 1,507 MB / 30s | +12 MB/min |
| **`fltmc unload FileCrypt`** | **1,507 → 814 MB（瞬时释放 693 MB）** | **0** |
| 再卸 wcifs / bfs | 无变化 | ~0 |
| 卸载后 90 秒复查 | 800 → 795 | **-3.3（池在收缩）** |

FileCrypt 在开机仅 1.3 分钟时已囤积 ~700 MB（≈540 MB/min），与历史速率完全吻合；可用内存从 ~900 MB 恢复到 8.6 GB。

## 五、根因：FileCrypt 扣留 I/O，一条线解释所有现象

泄漏源 = **`filecrypt.sys`**（Windows 沙盒与加密过滤器，实例挂在 **D:**）：

1. **四件套同步涨**：FileCrypt 扣住 I/O 不完成 → IRP、IRP_CTRL、文件对象、划痕缓冲全部堆积。磁盘传输仅 ~24/s，却每分钟堆积 16 万个 IRP——请求根本没到盘。
2. **SysMain 停止卡死**：其内存映射预取 I/O 被 FileCrypt 扣住，工作线程永久阻塞。
3. **安全模式不漏**：安全模式下 FileCrypt 不挂实例（无 I/O 经过）。
4. **为什么是 D:**：虚拟内存已移至 D:（系统托管），FileCrypt 实例正好挂在 D: 的 I/O 路径上。

---

## 六、修复与验证

- ✅ `sc config FileCrypt start= disabled`（持久生效）。
- ✅ **重启验证**：FileCrypt Stopped/Disabled；开机 2.3～4.3 分钟（历史最猛窗口）实测 120 秒：**758 → 758 MB，-0.3 MB/min**；可用内存 9.1 GB 且稳定。
- ⚠️ 副作用：禁用期间 Windows 沙盒不可用（本机未使用），升级后随系统文件替换恢复。
- 📌 **内存泄漏问题关闭。**

---

## 七、收尾：就地升级重装系统成功

- **修复前**：就地升级（setup.exe 保留文件和应用）因内存被泄漏耗尽而无法进行——安装程序卡在兼容性检查阶段，泄漏窗口（约 15 分钟）远小于升级所需时间。
- **修复后**：泄漏归零，用现有 ISO（`D:\Windows11iso.iso`，与本机同补丁级）执行就地升级，顺利完成。
- **一个细节**：安装程序未显示「保留个人文件和应用」级别的选项页，但实际默认按保留个人文件和应用执行——升级完成后个人文件与应用完好。
- **结果**：✅ WinSxS 组件库重建（4443 个缺失 manifest 修复），系统文件与驱动（含 filecrypt.sys）被替换，此前所有遗留问题（组件库损伤、SessionEnv 报错、切换用户黑屏等）随之解决。
